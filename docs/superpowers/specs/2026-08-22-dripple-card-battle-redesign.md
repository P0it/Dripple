# Dripple 카드 배틀 재설계

**작성일:** 2026-08-22
**상태:** 설계 확정, 구현 계획 대기
**대체 대상:** `docs/superpowers/specs/2026-04-05-dripple-design.md` 의 게임 규칙 부분

---

## 1. 배경

기존 구현(Phase 1–8)을 실제로 플레이한 결과 다음 문제가 확인되었다.

- AI가 문장을 **한 번도** 제출하지 못하고 매 턴 카드만 뽑는다.
- 타이머가 만료되면 게임이 정지한다.
- 라운드가 사실상 끝나지 않는다.
- 특수카드를 사람이 사용할 방법이 없다.
- 문장존의 카드 순서를 바꿀 수 없다.
- 전치사·접속사 카드가 사용 불가능한 상태로 덱에 들어 있다.

원인 분석 결과 개별 버그가 아니라 **게임 규칙 자체가 성립하지 않는** 구조적 문제였다.
따라서 버그 수정이 아니라 규칙 재설계로 접근한다.

## 2. 방향 전환

이 문서는 `CLAUDE.md`의 다음 항목을 **뒤집는다**. 구현 시 `CLAUDE.md`도 함께 갱신한다.

| 기존 결정 | 변경 후 |
|---|---|
| "Entertainment first — 학습 앱이 아니라 보드게임" | **목적은 아동 영어 학습, 형태는 진짜 카드 게임** |
| 게임 모드 프리셋 (Classic / Battle / Learning) | 단일 모드. 난이도와 타이머만 설정으로 조절 |
| 베팅/칩 시스템 | 폐기 |

**타깃:** 영어를 처음 배우는 6~10세.
학습 앱(듀오링고형 문제 풀이)이 아니라, 하다 보면 영어 어순이 익혀지는 **카드 대전 게임**을 만든다.
정답이 주어진 문제를 푸는 것이 아니라, 손에 든 카드로 만들 수 있는 문장을 스스로 찾아 낸다.

## 3. 게임 규칙

### 3.1 기본 구성

- 플레이어 4명 (사람 1 + AI 3). 멀티플레이 도입 시 인원 확장 가능.
- 초기 손패 7장.
- **단판 승부.** 먼저 손패를 전부 비운 사람이 승리.
- 라운드 개념 없음.

### 3.2 턴 구조 (러미 방식)

```
① 뽑기 (필수, 1장)
     덱 맨 위  또는  버린 더미 맨 위 (공개)
② 액션 1회
     ⓐ 문장 완성 — 손패에서 2장 이상 골라 배치, 문법 통과 시 내려놓음
     ⓑ 스킬 사용 — JUMP 또는 STEAL
     ⓒ 버리기   — 1장을 앞면으로 버린 더미에 올림
③ 턴 종료
```

문장을 완성해도 손패를 보충하지 않는다. 손패를 줄이는 것이 목표이기 때문이다.

**뽑을 카드가 없는 경우:** 덱이 비어 있고 버린 더미도 재활용할 수 없으면(맨 위 1장만 남음)
뽑기 단계를 건너뛰고 액션만 수행한다. 이 상태에서 3.6절의 종료 조건을 함께 검사한다.

### 3.3 문장 길이 규칙

**최소·최대 길이 제한을 두지 않는다.** 구조가 스스로 긴 문장을 유도한다.

| 액션 | 손패 증감 |
|---|---|
| 뽑기 + 2장 문장 | −1 |
| 뽑기 + 3장 문장 | −2 |
| 뽑기 + 5장 문장 | −4 |
| 뽑기 + 버리기 | 0 |

문법 엔진이 요구하는 2장이 자연 하한이다.
기존 `GameConfig.minSentenceLength = 5`는 **삭제한다.** 이 값이 AI가 문장을 제출하지 못한 직접 원인이었다.

### 3.4 허점 차단 규칙

기존 카드 게임들이 플레이테스트로 확립한 규칙을 그대로 적용한다.

| 규칙 | 막는 문제 | 출처 |
|---|---|---|
| 버린 더미에서 가져온 카드는 그 턴에 버릴 수 없다 | 두 사람이 한 장을 무한히 주고받는 교착 | 진 러미 |
| 덱 소진 시 버린 더미를 섞어 새 덱으로 (맨 위 1장은 남김) | 덱 고갈로 게임 진행 불가 | 덱빌더 공통 |
| 덱이 두 번째로 소진되면 손패가 가장 적은 사람 승 | 아무도 내지 않고 버티는 스톨링 | 러미 |
| 손패 1장이 남으면 자동으로 화면에 표시 | 선언을 깜빡해 지는 상황 (아동에게 부당) | UNO "우노!" 콜의 자동화 |
| 초기 배분 시 동사 1장 + 주어 가능 카드 1장 보장 | 첫 턴부터 아무것도 못 하는 손패 | 스크래블 "모음 없으면 재추첨" |

### 3.5 실패 처리

**문장 제출에 실패해도 액션을 소모하지 않는다.** 카드는 손패로 돌아가고 다시 시도할 수 있다.
배치 중 문법 유효성을 실시간으로 표시한다.
아동 대상이므로 실패를 처벌하지 않는다.

### 3.6 승리 판정

1. 손패 0장 → 즉시 승리, 게임 종료.
2. 덱이 2회 재활용된 뒤 다시 소진되면(`deckRecycleCount >= 2` 이고 덱이 빔) 손패가 가장 적은 사람 승.
   동수면 무승부.
3. 결과 화면 순위는 남은 손패 수 오름차순.

단판이므로 점수 누적은 없다.

## 4. 특수카드

| 카드 | 동작 | 액션 소모 | 매수 |
|---|---|---|---|
| **JOKER** | 만능 단어. 문장 안에서 어떤 품사로도 매칭된다. 문장 전체가 JOKER면 무효 | 문장 완성 액션에 포함 (스킬 아님) | 4 |
| **JUMP** | 다음 순서 플레이어의 턴을 건너뛴다 | 스킬 액션 | 3 |
| **STEAL** | 대상 플레이어를 지정 → 그 사람의 카드 1장을 무작위로 가져오고, 내 카드 1장을 지정해 준다 | 스킬 액션 | 3 |

- 기존 `SKIP`과 `JUMP`는 효과가 동일하므로 **JUMP 하나로 통합**한다. (아동에게 더 직관적인 명칭)
- 기존 `UNDO`(상대 문장존의 마지막 카드 제거)는 **삭제**한다. 러미 구조에서는 문장을 한 번에 완성해 내려놓으므로 중간에 무너뜨릴 대상이 존재하지 않는다.
- 상대 손패는 비공개이므로 STEAL은 **플레이어를 지정**하고 카드는 무작위로 가져온다. 주는 카드는 내가 지정한다.

## 5. 문법 엔진

### 5.1 현재 문제

`SentenceTemplates`가 21개 패턴을 문자열 배열로 하드코딩해 완전일치시킨다.
전치사구를 지원하려면 패턴이 수백 개로 폭발한다.
그 결과 덱의 전치사 4장·접속사 3장이 사용 불가능한 카드로 남아 있다.

### 5.2 재귀 청크 파서로 교체

```
NP  := (Art) (Adj)* Noun  |  Pronoun          명사구
PP  := Prep NP                                 전치사구
VP  := Verb (NP)? (Adv)? (PP)*                 동사구
S   := NP VP
```

예시:
- `the big cat` → NP
- `in the box` → PP
- `I like the cat in the box` → S (기존 방식으로는 불가능)

구현:
- 재귀하강 파서. 약 150줄 예상.
- `SentenceTemplates.validPatterns` (21개 배열) **삭제**.
- `StructureRule`만 교체한다. 나머지 4개 룰(`ArticleRule`, `NumberRule`, `SubjectVerbAgreementRule`, `AdjectiveOrderRule`)은 그대로 유지한다.
- JOKER는 파서 레벨의 와일드카드 토큰으로 처리한다. 현재의 `'*'` 문자열 처리 방식은 제거한다.

### 5.3 범위

접속사와 시제 변화는 **범위 밖**이다. 6~10세 초급에 과하고 검증 복잡도가 크게 오른다.
덱에서 접속사 카드를 제거한다.

## 6. AI 재설계

### 6.1 현재 문제

`AIPlayer._findBestSentence()`가 하드코딩된 4가지 패턴만 시도하며 최대 4장까지만 조합한다.
`minSentenceLength = 5` 조건을 영원히 통과하지 못해 **AI는 매 턴 `drawCard()`만 호출**한다.

### 6.2 새 탐색 방식

청크 문법이 생기면 탐색이 자연스럽게 정의된다.

- 손패를 품사별 버킷으로 분류.
- 문법 규칙을 위에서 아래로 채우는 **백트래킹 탐색**. 슬롯별 후보만 검사하므로 순열 전수조사(7! = 5040)를 피한다.
- 유효한 문장 후보 중 난이도 정책에 따라 하나를 선택.

| 난이도 | 최대 문장 길이 | 선택 정책 | 무의미한 버리기 확률 |
|---|---|---|---|
| 쉬움 | 3장 | 무작위 | 30% |
| 보통 | 5장 | 유효한 후보 중 무작위 | 10% |
| 어려움 | 제한 없음 | 최장 | 0% |

특수카드 사용 판단은 기존 `_tryPlaySpecial` 로직을 유지하되 UNDO 분기를 제거한다.

### 6.3 AI 진행 소유권 이전

현재 `_processAITurns()`를 `game_screen.dart`가 호출한다.
그 결과 타이머 만료로 턴이 넘어가면 AI 루프를 돌리는 주체가 없어 **게임이 정지한다.**

턴 진입 시 `GameNotifier`가 스스로 AI 진행을 트리거하도록 소유권을 옮긴다.
이 변경으로 "특정 경로로 턴이 넘어가면 멈춘다" 부류의 버그가 구조적으로 사라진다.

## 7. 카드 덱 재구성

### 7.1 구성비

| 품사 | 매수 | 비고 |
|---|---|---|
| 대명사 | 12 | 주어 확보 |
| 관사 | 10 | a / an / the |
| 명사 | 26 | 단수·복수 짝 |
| 동사 | 26 | 일반동사 + be동사(am/is/are) + 조동사(can) |
| 형용사 | 12 | `adjOrder` 유지 |
| 부사 | 6 | |
| 전치사 | 8 | in / on / under / with 각 2장 |
| 특수 | 10 | JOKER 4, JUMP 3, STEAL 3 |
| **합계** | **110** | |

- 접속사 3장 제거.
- 동사 비율을 22% → 24%로 상향한다. 손패 7장에 동사가 0장일 확률이 여전히 약 14%이므로 3.4절의 초기 손패 보장 규칙이 반드시 함께 필요하다.
- be동사 추가에 따라 `SubjectVerbAgreementRule`이 am/is/are를 올바르게 처리하는지 검증한다.

### 7.2 품사별 시각 구분 (몬테소리 문법 기호)

글자를 아직 잘 읽지 못하는 아이가 문장 구조를 색과 도형으로 파악하게 한다. 100년간 검증된 표기법이다.

| 품사 | 색 | 도형 |
|---|---|---|
| 명사 | 검정 | 큰 삼각형 |
| 관사 | 하늘색 | 작은 삼각형 |
| 형용사 | 남색 | 중간 삼각형 |
| 대명사 | 보라 | 삼각형 |
| 동사 | 빨강 | 원 |
| 부사 | 주황 | 작은 원 |
| 전치사 | 초록 | 초승달 |

`WordCard`에 품사별 색상·도형을 파생 속성으로 노출한다. 카드 데이터에 직접 저장하지 않는다.

### 7.3 ID 생성

`CardDeck._idCounter`는 전역 가변 정적 변수다. 테스트 격리를 깨고 멀티플레이에서 충돌 위험이 있다.
인스턴스 소유 카운터로 변경한다.

## 8. UI

### 8.1 Flame 유지

카드 게임의 물성을 살리는 것이 이 프로젝트의 의도이므로 Flame을 유지한다.
파티클, 카드 흩날림, 3D 플립 등 향후 연출 확장의 근거지가 된다.

접근성(스크린리더가 Flame 캔버스를 읽지 못함)은 이 결정의 알려진 비용이며, 별도 과제로 남긴다.

### 8.2 문장존 재배열 (신규)

현재 `undoPlacement()`는 문장존의 **마지막 카드만** 되돌린다.
자유로운 재배열이 없으면 아이가 막혔을 때 빠져나올 수 없다.

Flame 내부에 직접 구현한다. 약 200줄 예상.

- 문장존 컴포넌트에 `DragCallbacks` 활성화 (현재 `withDrag: false`).
- 드래그 중 x좌표로 삽입 인덱스를 계산하고, 나머지 카드를 `MoveEffect`로 밀어낸다.
- 드롭 시 인덱스를 확정하고 `GameNotifier.reorderSentence(from, to)`를 호출한다.
- 문장존 밖으로 끌어내면 손패로 반환한다 (`removeFromSentence(index)`).

### 8.3 특수카드 사용 UI (신규)

현재 `playSpecialCard()`는 구현되어 있으나 **호출하는 UI가 없다.** 사람은 특수카드를 쓸 수 없다.

- 손패의 특수카드를 탭하면 스킬 사용 시트를 연다.
- JUMP: 확인만.
- STEAL: 대상 플레이어 선택 → 줄 카드 선택.

### 8.4 턴 상태 표시

- 현재 턴이 뽑기 단계인지 액션 단계인지 표시.
- 버린 더미를 화면에 표시하고 탭으로 가져갈 수 있게 한다.
- 각 플레이어의 남은 손패 장수를 항상 표시한다. 1장 남으면 강조.

### 8.5 타이머

기본 OFF (`turnTimerSeconds = 0`). 설정에서 켤 수 있다.
켠 경우의 만료 처리도 재작성한다 (현행은 만료 시 게임 정지).

## 9. 상태 구조 변경

| 변경 | 이유 |
|---|---|
| `GameState.discardPile` 추가 | 버린 더미 개념이 없어 낸 카드가 소멸 중 |
| `TurnPhase { draw, action }` 추가 | "뽑기 필수 → 액션 1회" 강제 |
| `GameState.drawnFromDiscardThisTurn` 플래그 | 되버리기 무한루프 차단 |
| `GameState.deckRecycleCount` 추가 | 덱 2회 소진 종료 조건 판정 |
| `GameConfig.minSentenceLength` 삭제 | 규칙에서 제거 |
| `GameState.currentRound` / `totalRounds` / `GamePhase.roundEnd` 삭제 | 단판 승부 |
| `GameConfig.playerCount` 기본값 2 → 4 | |
| `GameConfig.turnTimerSeconds` 기본값 30 → 0 | |
| AI 진행 트리거를 `game_screen.dart` → `GameNotifier` | 턴 정지 버그의 근원 |

## 10. 삭제 목록

- `GameConfig.minSentenceLength`
- `SentenceTemplates.validPatterns` (21개 배열) 및 파일 전체
- `CardType.undo` 및 관련 분기
- `CardType.skip` (JUMP로 통합)
- 덱의 접속사 카드 3장
- 라운드 관련 상태 및 `_startNewRound` / `continueToNextRound` / `_RoundEndOverlay`
- `AIPlayer._findBestSentence` / `_findCompletionCards` (백트래킹 탐색으로 대체)

## 11. 테스트 계획

현재 문법 엔진에만 21개 테스트가 있고 게임 로직 테스트는 0개다.

**문법 엔진**
- 기존 21개 테스트가 새 파서에서도 통과하는지 확인 (회귀).
- 전치사구 신규 케이스: `I like the cat in the box`.
- JOKER 와일드카드 매칭.
- JOKER만으로 구성된 문장 거부.

**턴 규칙**
- 뽑기 없이 액션 시도 → 거부.
- 버린 더미에서 가져온 카드를 같은 턴에 버리기 → 거부.
- 덱 소진 → 버린 더미 재활용.
- 덱 2회 소진 → 손패 최소인 플레이어 승리.
- 손패 0장 → 즉시 게임 종료.
- 문장 제출 실패 시 액션이 소모되지 않음.

**특수카드**
- JUMP → 다음 플레이어가 건너뛰어짐.
- STEAL → 양쪽 손패 수가 보존됨(교환).

**AI**
- 유효한 문장을 만들 수 있는 손패에서 실제로 제출하는지 (현재 실패하는 지점).
- 난이도별 최대 문장 길이 준수.
- 문장 불가 손패에서 버리기를 선택하는지.

**초기 배분**
- 모든 플레이어의 초기 손패에 동사 1장 이상, 주어 가능 카드 1장 이상.

## 12. 범위 밖

- 온라인 멀티플레이 (Firebase). 이번 변경은 그 토대만 정리한다.
- 접속사, 시제 변화, 의문문, 부정문.
- 접근성(Semantics) — Flame 유지 결정의 알려진 비용.
- Rive 캐릭터 에셋, 오디오 에셋, AdMob.
- 영구 저장(설정·진행도).

## 13. 미결 사항

- 승리 시 연출 수준 (파티클 여부) — Flame 유지 결정에 따라 이후 판단.
- AI 턴 진행 속도 기본값 (현행 800ms). 4인이므로 한 바퀴 대기가 2.4초가 된다. 플레이 후 조정.
